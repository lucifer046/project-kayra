# pyproject/Poetry/Pipenv layer on purpose (see docs/development/DEPENDENCIES.md).
#
# Supported interpreters: CPython 3.10 - 3.14 (3.15 is not released; see DEPENDENCIES.md).
# Supported platforms:    Windows 10/11 (x64) and Linux x86_64 (Arch/Omarchy first).
#
# Platform-specific packages carry PEP 508 environment markers, so the same file installs
# cleanly everywhere and never asks Linux to build a Windows-only wheel:
#   sys_platform == "win32"  -> Windows only (desktop automation, Win32 window control)
#   sys_platform == "linux"  -> Linux only   (uinput pointer injection for gestures)
#
# Version floors are pinned where a breaking change is known upstream; ceilings only where
# a newer release was MEASURED to break Kayra (each one says why).

# ── ONNX Runtime is deliberately NOT pinned here. `setup.py` owns it. ──────────────────────
#
# There are three mutually exclusive distributions - onnxruntime, onnxruntime-gpu and
# onnxruntime-directml - and they all install into the SAME `onnxruntime/` package directory.
# Listing one here would mean:
#
#   * on an NVIDIA machine, every `pip install -r requirements.txt` silently overwrites the GPU
#     build with the CPU one, and speech synthesis quietly stops using the GPU;
#   * two distributions claiming the same files, so uninstalling either breaks the other.
#
# `kokoro-onnx` above already declares `onnxruntime>=1.20.1`, so the CPU wheel arrives as a
# transitive dependency regardless. `setup.py::configure_speech_runtime` runs AFTER this file
# is installed and repairs the environment: it selects the right variant for the detected
# hardware, removes the conflicting ones, installs the matching NVIDIA CUDA/cuDNN runtime
# wheels, and then PROVES a CUDA session can initialize before claiming GPU support.
#
# The package name is `onnxruntime-gpu`; the Python import is and remains `import onnxruntime`.
# There is no module named `onnxruntime_gpu`.
#
# Run `python setup.py` rather than installing ONNX Runtime by hand.

# ── Desktop UI ────────────────────────────────────────────────────────────────
# PySide6-ESSENTIALS, not the full PySide6 distribution. Essentials omits QtWebEngine and the
# other add-on modules, which keeps the install ~200MB instead of ~1GB and — more importantly —
# guarantees no browser runtime is shipped to render the interface. The UI is native Qt widgets.
# Measured cost: +262ms to reach a painted window, +20MB RSS.
# Native desktop UI (src/kayra/ui). Kayra runs headless without it.
# PySide6 6.12.0 aborts the interpreter on CPython 3.10/3.11 ("Fatal Python error: none_dealloc"
# — a shiboken refcount bug that 3.12+'s immortal None hides). Measured with tests/test_ui.py:
# 6.12.0 crashes on 3.10 and 3.11, 6.11.3 and 6.10.3 pass all checks on 3.11, 6.12.0 passes on
# 3.12-3.14. Hence a ceiling for the older interpreters only.
PySide6-Essentials>=6.6,<6.12; python_version < "3.12"
PySide6-Essentials>=6.6; python_version >= "3.12"
